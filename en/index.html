Finder learned tabs.
Then it stopped.

SuperFinder finishes the set: an address bar, search as a place, a layered bookmarks bar, a start page. If you know Chrome, you already know it; twenty years of habits carry straight over.

⌘Laddress ⌘Tnew tab ⌘Fsearch

The address bar does three things

Paste a path, hit Return: the kind you copy out of a terminal or an AI chat. Type ~ and Tab through each level. One click copies the current path. It's live in the window up top.

Search is a place

Search results go back, bookmark, and restore like folders; both are the same thing here, a Place.

Bookmarks bar & start page

Bookmarks group into folders with icons, as many as you need. ⌘T opens a start page; recently closed tabs come back whole.

Close. Return.
Everything's here.

⌘Q saves the tab groups, pane trees, and shelf references. Reopen, and the scene is exactly as you left it. Real browsers restore sessions. So does this.

Whole trees come back

Each pane tree's structure, ratios, and folders return together.

Crashes count too

Snapshots land on disk continuously, throttled; a crash gets the same treatment as a clean quit.

A workspace you split,
and get back.

The high-frequency move in heavy file work is compare. Here it happens inside the tab: four-way splits, grip swaps, layouts you can name and restore in a new tab. Dual-pane managers handle seeing two folders; this saves your whole workspace.

Recursive splits, in-tab

Right-click the blank, split four ways, as deep as you need; drag an edge grip to swap in place. One window, one browser.

Saved layouts

The ▦ button names the split structure, each pane's folder, and its view mode; click the chip in the bookmarks bar and the same scene reopens in a new tab.

Staging shelf

Drop in and it records a reference; the original stays put. It follows the session and survives restarts; the one move happens when you drag out.

Select. Act in place.

Select files and the sidebar offers the matching tools: convert, resize, remove background, merge PDFs, transcode video. Eleven built in; plugins add more. Everything lands in place, previewed and confirmed, revert with ⌘Z.

The workbench saves
a place for you.

Write a script and it becomes a sidebar tool. bash, Python, Node, whatever you use; package it as one file and import it in settings.

What you can build

Archive photos by date, generate files from a CSV, pipe documents through your own API. Anything a script can do becomes a file tool.

Same safety net

Plugin output lands like built-in tools: previewed first, collisions yield, ⌘Z reverts.

Writing one

Export the dev kit from settings: the spec and two working examples (archive by date, CSV extract), then adapt them. Hand it to an AI agent if you like.

The boundary

Plugins are code you installed; their networking is your responsibility. The app itself stays offline.

Fast, but never out of bounds.

What got browser-ified is the operating, not the boundaries.

Trash is the only exit no permanent delete

Deletion always goes to the system Trash. There is no path around it inside the app, and no preference to change it.

No account. No cloud. No telemetry.

The app's own code contains no networking and no analytics. External plugins are user-installed code; their networking is the user's responsibility. Neither does this site (zero third-party requests).

Every write action undoes full audit trail

Moves, copies, renames, and tool products take effect immediately; ⌘Z reverts silently, and every write lands in an auditable ledger watched by 1,947 unit tests. The Finder-parity basics (batch rename, Quick Look, ⌘1-4 views) are all here too; no need to dwell on them.
